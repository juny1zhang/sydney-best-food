# 悉尼吃什么 · Sydney Eats

悉尼 13 个类别里口碑最好的 88 家餐厅，配一个 2026 年 12 月的日历：把每天要吃的店排进去，订好的餐厅会把日期涂成橙色，点开能看到餐厅、类别标签、营业时间和简介。

- **榜单**：中餐、火锅、烤肉、日料、韩餐、东南亚、中东 / 地中海、意大利 / 披萨、法餐 / 欧陆小馆、现代澳洲、海鲜、牛排馆、早午餐 / 甜品，共 88 家。多数类别综合 2026 SMH Good Food Guide、AGFG、Gourmet Traveller、World’s 101 Best Steak、50 Top Pizza、Broadsheet / Time Out 等来源；火锅、烤肉和几家榜单没收录的店主要看小红书和 Google 地图上的评价。每家都附“评价依据”和来源链接，营业状态核对于 2026-10-12。
  - 可以搜索（店名、中文名、区域、标签、简介；常见英文词如 dim sum、wagyu、pizza 会对应到中文，“日本料理”“中国菜”这样的说法也认；多个词要同时满足，比如 steak cbd 只找 CBD 的牛排馆）、按价位筛选，列表还能按默认排名、小红书口碑、TripAdvisor 评分或价格排序。选中的类别、价位和排序会记在浏览器里，下次打开还在。
  - “全部”视图默认只露出一排类别（至少两个），其余可以展开。
  - 列表上标出小红书口碑（好评 / 褒贬不一）和 TripAdvisor 评分；小红书帖子太少、TripAdvisor 评论不足 20 条的不显示标签，详情页里仍能看到整理的评价。
- **餐厅详情页**：点店名打开（地址是 `#r/<id>`，可以直接分享）。有营业时间和出处、菜单怎么点、大概花多少、招牌菜、餐厅官网上的图片、小红书和 TripAdvisor 的口碑（夸的和吐槽的），也能直接加入日历。不是每家都有官网菜单链接和图片；官网图片失效时会自动隐藏。
- **日历**：橙色 = 已预订，蓝色 = 自己选好的，浅绿 = 在新西兰，虚线框 = 有航班的日子（12/2、12/6、12/9、12/20）。每天分午餐、晚餐两顿。
  - 悉尼的空日子可以从榜单搜索、挑选，任何一天都可以手动记一家榜单外的店。挑选列表跟着榜单当前选中的类别走，已在日历里的店会注明排在哪天。
  - 订好位以后点“标记为已订”，可以填时间，日期就变成橙色、算进“已订”。新西兰行程里的两家（12/6 Advieh、12/12 Kika）是写死的预订。
  - 会提示的情况：店家通常不做这一顿、那天通常休息，或者已公布 12 月某几天休息（比如圣诞、跨年）、某天某一顿不营业。只提示，不拦着。
  - 手机和平板（宽 ≤ 1047px 或高 ≤ 500px）上，当天安排从底部弹出。
- **共享**：配好 Supabase 后，所有打开网站的人编辑的是同一份日历，改动实时同步。网站没有登录，拿到链接的人都能改；publishable key 也在前端代码里，懂技术的人不用打开网站也能直接改这份日历。
  - 顶部的同步状态点一下能看说明：“连接中…”、“实时同步”、“连不上”（读不到共享日历，正在重试）、“未同步”（改动还没存上，会自动重试）。
  - 还没存到共享日历的改动会先记在这台设备上，刷新或关掉页面也不会丢，连上后自动补发。请求 10 秒没有回应就算失败重试，不会一直卡住。
  - 浏览器里的 localStorage 同时是缓存，让页面秒开；没配 Supabase 时（比如跑测试），选择只存在本机，同一浏览器的多个标签页互相同步。
- **意见反馈**：页面底部的表单，写进 Supabase 的 `feedback` 表。访客只能提交、不能查看；在 Supabase 控制台 Table Editor → `feedback` 里看。没配 Supabase 时表单不显示。

## 开发

```bash
npm install
npm run dev          # 本地开发 http://localhost:5173
npm test             # Vitest 单元测试 + 组件测试
npm run typecheck
npm run build        # 输出到 dist/
npm run check:links  # 检查数据里的图片、菜单和来源链接还能不能打开
```

技术栈：Vite + React 18 + TypeScript，纯静态站点。Supabase 客户端按需加载，不拖慢首屏。

`check:links` 需要能上网：图片或菜单链接坏了就以非零状态退出，其他链接（来源、官网、点评页）只列出来提醒。图片都直接引用餐厅官网，官网换图后要靠它发现。

## 共享日历（Supabase）

建表 SQL 在 `supabase/migrations/`：`picks` 表每顿饭一行，只接受 `dec-2026` 这一份计划，最多 62 行；`pick` 列是 JSON，里面可以带 `booked` 和 `time`（用户标记的已订和时间）。`feedback` 表只开放写入。连接信息写在 `.env`（`VITE_SUPABASE_URL`、`VITE_SUPABASE_PUBLISHABLE_KEY`）：publishable key 本来就是给浏览器用的，可以提交。`.env.test` 把它们清空，所以测试不会碰到真实数据。

线上项目里两份迁移的版本号（`20261012005256`、`20261012050514`）和仓库里的文件名不一样；以后要用 Supabase CLI 的 `db push`，先用 `supabase migration repair` 对齐。

## 部署到 Vercel

`vercel.json` 已经写好构建设置（`npm ci` → `npm run build` → 输出 `dist/`）。在 Vercel 控制台 **Add New → Project → Import Git Repository**，选 `juny1zhang/sydney-best-food` 直接 Deploy 即可；之后每次 push 都会自动重新部署。

## 数据

| 文件 | 内容 |
| --- | --- |
| `src/data/restaurants.json` | 餐厅榜单：类别、排名、中文名、区域、价位、奖项徽章、标签、简介、订位提示、营业餐段、营业时间（`hours`、`hoursSource`）、每周休息日（`closed`，0 = 周日）、12 月已公布的休息日期（`closedDates`）和某天不营业的那一顿（`closedMeals`）、获奖原文与来源链接、小红书口碑（`xhs`）、TripAdvisor（`ta`） |
| `src/data/details.json` | 详情页：菜单概况、官网菜单链接、招牌菜（中英文名、简介、图片）、餐厅照片、资料来源。图片只用餐厅或所属集团官网上的 |
| `src/data/december.ts` | 12 月每天在哪、当天行程、航班、节日，以及新西兰行程里已订的两家餐厅 |

改榜单直接编辑 `restaurants.json`，`rank` 决定类别内的顺序。`src/data/restaurants.test.ts` 会检查：恰好 13 个类别、每类至少 3 家且排名连续、id 唯一、每家都有简介和来源、价位合法、休息日和营业时间来源格式正确。`src/data/details.test.ts` 检查详情只描述榜单上的店、每家都有菜单概况和招牌菜，图片和出处都是 https、且不是社交媒体、点评站或图库的图。

中文名只填餐厅自己用、或中文平台上通用的名字，不自己翻译，所以多数西餐厅没有中文名。营业时间来自 2026 年 10 月的搜索，来源说法不一的店不标休息日，只在营业时间里写明。
